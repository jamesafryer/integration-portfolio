# Integration Portfolio

A learning portfolio by James Fryer documenting the progressive development of enterprise integration, systems analysis, and implementation skills.

## Purpose

This repository documents my journey learning enterprise integration, APIs, Python, SQL, and systems design through a fictional veterinary practice called Cedar Creek.

Rather than building unrelated coding exercises, each project explores a realistic business integration challenge commonly encountered in enterprise software like data synchronization, APIs, workflow automation, fault recovery, or system communication.

Through these projects, my aim is to demonstrate and build a level of understanding and proficiency not provided by my current experience. 

## Repository Structure

Each project builds on the previous and references a specific business scenario. Those scenarios and the challenges they pose will be addressed in the README document of each 'project'. 

While each project is separate, they are all part of the larger fictional business of Cedar Creek because enterprise systems rarely exist in isolation. Keeping the same organization allows each project to build naturally on the previous one while reflecting how real business systems evolve over time.

Also included in each project folder are files separating code, diagrams, documentation, and data. The purpose of this separation is to provide organization and to demonstrate my ability to create relevant and useful documentation.

## Learning Philosophy

As a former teacher, I understand that lessons can feel easy and then we can get lost when it comes to application. For that reason, I wanted to create a sample portfolio both as a demonstration to potential employers and as a practical exercise so I can confirm that what I've learned is absorbed.

Because I do not have a business in which to demonstrate these things, I have decided on using a fictional business so that this project is honestly and humbly framed as an experiment and not passed off as real-world work experience.

I have chosen implementation/integration as my target specifically because it combines some of my favorite parts of various other positions I have held: interaction, problem solving, creating effective workflows, and technical curiosity. Understanding systems and using that understanding to help peers, customers, and stakeholders understand how it can benefit them.

Like with most fields, the best way to learn is to do. As much as I can read job descriptions to figure out how the job works, the most realistic demonstration and skill-building exercise is to just try it! 

## Roadmap

For this repository, the process of its creation has been:
- Phase 1: Understand the business problem
- Phase 2: Model the data
- Phase 3: Build the synchronization
- Phase 4: Introduce APIs
- Phase 5: Handle failures and recovery
- Phase 6: Expand into larger multi-system workflows

This repository is intentionally iterative. Documentation, architecture, and implementations are expected to evolve as my understanding of enterprise integration grows.
